Sleepy virtual machines implementation plan
===========================================

Purpose
-------

This document gives the implementation sequence for VM network activity tracking,
automatic VM sleep, and network-triggered wake. It is a handoff document. Complete
the commits in order. Do not combine review chunks.

The work has three phases:

1. Track the last packet activity of each VM and provide a Go method to read it.
2. Snapshot and stop an idle VM when its specification has is_sleepy set.
3. Restore a sleeping VM when a packet reaches its TAP interface.

Each review chunk contains 5 to 7 commits. Every commit must build and must keep
the unit tests green. A review chunk is complete only when all acceptance checks
for that chunk pass.

Commit sizing rules
-------------------

Give each commit one primary behavior or contract change. A commit can include
the tests and focused documentation for that behavior. Do not combine an API
change, a runtime transition, and recovery logic in one commit. If a commit needs
more than one sentence to state its primary outcome, split it and add another
review chunk. Keep every review chunk at 5 to 7 commits after a split.

Required design decisions
-------------------------

These decisions are part of the plan. Do not change one inside an implementation
commit. Propose a small design update first if host evidence makes a decision
invalid.

1. Attach a TCX eBPF program to ingress and egress of tap0 in each VM network
   namespace. Do not attach to vh-<user-id>. Atlas WG Mesh owns that end of the
   veth pair. Do not attach to vg-<user-id>. EgressNone removes that interface,
   but tap0 remains available for the VM lifecycle.
2. Require a host Linux kernel that supports TCX, Linux 6.6 or newer. Check the
   required BPF program type, map types, helpers, and attach types at daemon
   startup. Return one clear startup error if a requirement is absent. Do not
   silently use a polling-only fallback.
3. Count every Ethernet frame in both directions in the first implementation.
   Do not parse TCP, UDP, IPv4, or IPv6. This makes ARP and neighbour discovery
   able to wake a VM before the first IP packet. Add filtering only after host
   measurements show a specific source of unwanted traffic.
4. The eBPF program must only observe and signal. It must always return TCX_NEXT.
   It must not drop, redirect, clone, or change a packet.
5. Key shared BPF maps by the stable VM user ID. Load one small program instance
   for each VM and rewrite a read-only virtual_machine_user_id constant before
   loading it. Use the same program instance for the ingress and egress links.
6. Keep eBPF programs, maps, and links owned by the metald process. Do not pin
   them in bpffs in the first version. A metald restart attaches new links and
   initializes a new activity baseline. This can delay sleep by one idle timeout,
   which is safe. It must never cause an early sleep.
7. Use github.com/cilium/ebpf and bpf2go. Commit generated Go files so a normal
   make build does not need Clang. Keep the C source and generation command in
   internal/network. Limit generated output to linux/amd64 and linux/arm64, which
   are the architectures produced by the current Makefile.
8. The Go activity method is:

       LastNetworkActivity(ctx context.Context, request vm.NetworkActivityRequest) (vm.NetworkActivity, error)

   NetworkActivity contains LastSeenAt and HasBeenSeen. A newly attached monitor
   returns its attachment time with HasBeenSeen false. The sleep policy uses the
   attachment time as the safe baseline.
9. eBPF stores bpf_ktime_get_ns() in a regular hash map. Go reads CLOCK_MONOTONIC
   and converts the age to a UTC wall-clock time. Do not put a wall-clock value in
   the BPF map. Wall-clock changes must not make a VM sleep early.
10. Add IsSleepy bool to vm.Specification and expose it as is_sleepy in the create
    request and desired response. Add PUT /v1/vms/{id}/sleep-policy with the full
    body {"is_sleepy": true|false}. A real change raises the desired generation.
11. Add this host configuration. Support is off by default for a safe rollout:

        [sleep]
        enabled = false
        idle_timeout = "30m"

    Parse idle_timeout with time.ParseDuration. When enabled, require a positive
    duration. This is one Metal-wide value. Apply the same value to every VM on
    this host that has IsSleepy set. Do not add an idle timeout to Specification,
    DesiredRecord, ObservedRecord, any VM API request, or any VM API response.
    Use the existing 5-second VM reconciliation interval to evaluate running VMs.
    Do not add one polling goroutine per VM.
12. sleeping is an observed state only. The desired state remains running while
    automatic sleep is active. Add StateSleeping to observed-state validation.
    Do not accept sleeping in a power request or desired record.
13. Extend the existing Runtime.Start and Runtime.Stop paths with explicit modes:

        StartNormal
        StartFromSleepSnapshot
        StartFromSleepSnapshotPaused
        StopShutdown
        StopWithSleepSnapshot

    Runtime.Stop with StopShutdown keeps the current Ctrl+Alt+Del and bounded
    kill behavior. Runtime.Stop with StopWithSleepSnapshot pauses the guest,
    creates a full snapshot, and terminates the Firecracker process. Runtime.Start
    with StartFromSleepSnapshot restores and resumes the VM-local snapshot.
    Runtime.Start with StartFromSleepSnapshotPaused restores it without running
    the vCPUs. Runtime.Start with StartNormal keeps the current warm-image and
    cold-boot behavior.
14. Keep POST /v1/vms/{id}/restart as a guest restart. It uses StopShutdown and
    StartNormal. A stop followed by snapshot restore is a warm VMM restart, not a
    guest restart. Do not silently change the API contract.
15. Store VM-local sleep artifacts below machines/<id>/sleep/. Do not put them in
    the image snapshot store. They belong to one VM and never leave the host.
    They are removed when the VM is destroyed or the snapshot is invalidated.
16. Use a full memory snapshot. Do not use Firecracker diff snapshots in this
    version. Pause before snapshot creation. Keep Firecracker file syncing enabled.
    Firecracker drains and syncs the block device during snapshot creation, so
    keep the existing ZFS VM volume and do not create a second disk snapshot.
17. Publish a snapshot as one atomic directory operation. Firecracker writes into
    a new generation directory inside its jail. After the files are complete,
    move the directory to machines/<id>/sleep/generations/<n>. Write the manifest
    last through platform.WriteFile, then terminate Firecracker. A manifest is
    the only indication that a snapshot is complete. Publishing before process
    termination makes an interrupted warm stop recoverable without guessing.
18. Never overwrite a memory file that a restored Firecracker process can still
    map. Use a new generation for every sleep. Keep the loaded memory file in the
    jail for the life of that process. Remove the prior external generation only
    after the next snapshot is complete and the old Firecracker process is gone.
19. A sleep manifest contains the VM ID, user ID, specification generation,
    restart generation, Firecracker compatibility value, creation time, state
    file name, memory file name, and expected file sizes. Validate every field
    before restore. Derive all directories from the VM ID. Never accept a path
    from the manifest.
20. A missing, partial, incompatible, or corrupt sleep snapshot is an operation
    failure. Do not silently cold boot because that loses the in-memory workload.
    A controller-requested restart or an operator disabling is_sleepy can
    explicitly discard the snapshot and use StartNormal.
21. The trigger packet can be lost while no Firecracker process has tap0 open.
    eBPF cannot hold an arbitrary packet until userspace restores a VM. The wake
    path must be quick, but clients must retry. The end-to-end test uses TCP or an
    explicit retry. Do not claim reliable delivery of the trigger packet.
22. One VM operation lock owns the idle decision, snapshot stop, state update,
    and wake restore. A wake event can wait for this lock. It must not run a
    second Firecracker operation at the same time.

Target data flow
----------------

Running traffic:

    external or host packet
      -> VM route in metal-<id>
      -> tap0 TCX egress hook
      -> update activity_by_user_id[user_id]
      -> Firecracker TAP file descriptor
      -> guest eth0

    guest packet
      -> Firecracker TAP file descriptor
      -> tap0 TCX ingress hook
      -> update activity_by_user_id[user_id]
      -> namespace routing and veth

Automatic sleep:

    VM reconcile pass
      -> confirm desired running and is_sleepy
      -> read last network activity
      -> confirm idle timeout expired
      -> take the VM operation lock
      -> inspect and re-read activity
      -> Stop(..., StopWithSleepSnapshot)
           -> pause vCPUs
           -> create full state and memory files
           -> sync and validate files
           -> publish the sleep manifest
           -> terminate Firecracker without guest shutdown
      -> write observed state sleeping

Network wake:

    packet on sleeping tap0
      -> TCX program updates activity
      -> TCX program changes wake state from armed to notified
      -> TCX program submits one wake event to the ring buffer
      -> Go ring reader resolves user ID to VM ID
      -> wake reconciler calls Manager.WakeFromNetwork
      -> Manager takes the VM operation lock
      -> confirm desired running, is_sleepy, and observed sleeping
      -> Start(..., StartFromSleepSnapshot)
      -> disarm wake notification
      -> write observed state running

State rules
-----------

Use this table in manager tests. Each row is required behavior.

Desired     Observed or runtime     is_sleepy   Action
running     running                 false       Keep running. Do not evaluate idle time.
running     running                 true        Sleep only after the idle timeout and final recheck.
running     sleeping                true        Keep sleeping until a wake event.
running     sleeping                false       Discard policy hold and restore from the snapshot.
paused      sleeping                any         Load the snapshot and leave the loaded VM paused.
stopped     sleeping                any         Discard the sleep snapshot and report stopped.
destroyed   sleeping                any         Remove runtime and sleep artifacts before network and disk.
running     sleeping with restart   any         Discard the sleep snapshot and do a normal guest restart.
running     failed snapshot         true        Report operation failure. Do not cold boot automatically.

Eligibility rules
-----------------

A VM can enter automatic sleep only when all these conditions are true:

* Host sleep support is enabled and the Metal-wide idle_timeout is positive.
* The desired state is running.
* IsSleepy is true.
* The observed generation equals the desired generation.
* The observed restart generation equals the desired restart generation.
* Runtime inspection reports running.
* No VM operation is already incomplete.
* The activity monitor is attached and has a baseline.
* The activity age is at least the Metal-wide idle_timeout.

Do not sleep a paused, stopped, failed, unknown, created, or destroyed VM. Do not
sleep while a specification or restart generation is pending.

Snapshot and crash rules
------------------------

The StopWithSleepSnapshot implementation must be repeatable after interruption.
Use these recovery rules:

* No manifest and runtime running: start a new snapshot generation.
* No manifest and runtime paused: remove an incomplete generation, recheck
  activity, and either resume or create a new full snapshot.
* No manifest and runtime stopped: inspect pending files. Publish them only when
  every artifact validates against recoverable operation metadata. Otherwise
  report a failure and preserve the files for diagnosis.
* Complete manifest and runtime paused: terminate Firecracker and report sleeping.
* Complete manifest and runtime stopped: report sleeping without making a new
  snapshot.
* Manifest exists but files do not validate: report phase sleep-snapshot as
  failed. Keep all evidence for an operator.
* Runtime running and an old external generation exists after a successful wake:
  remove only the external generation that is no longer the active backing file.
* On metald restart, attach activity tracking before manager reconciliation. Use
  the attachment time as a new safe baseline for running VMs.
* On metald restart with a sleeping VM, validate the manifest, attach tap0,
  arm wake notification, and keep the VM sleeping.

The observed record needs enough state to recover without guessing. Add a sleep
object with these fields:

    eligible_at
    requested_at
    snapshot_generation
    snapshot_created_at
    last_network_activity_at

Keep paths and local compatibility detail out of the controller response. Paths
are derived by the Firecracker runtime. Keep local error details in OperationError.

Validation list for every review chunk
--------------------------------------

Run commands from metal/.

    gofmt -w <changed Go files>
    go test ./...
    go vet ./...
    go test -race ./...
    make openapi
    make build

For a chunk that changes eBPF source, also run:

    go generate ./internal/network/...
    git diff --exit-code -- internal/network

Run the generation diff check only after generated results are staged or compare
against a clean checkout in CI. The purpose is to fail when committed bindings do
not match the C source.

For Phase 1 and Phase 3 network chunks, run the root-only test on both supported
host architectures when runners are available:

    sudo -E go test -tags integration -v ./internal/network/

For Phase 2 and the final end-to-end chunk, use the prepared disposable host:

    sudo -E go test -tags integration -v ./internal/firecracker/
    sudo metal/test/integration/ssh-test.sh
    sudo metal/test/integration/sleepy-vm-test.sh

Required failure tests
----------------------

Do not consider the work complete without deterministic coverage of these cases:

* eBPF program load rejected by the kernel.
* TCX ingress attach succeeds and egress attach fails.
* tap0 is deleted and recreated.
* The VM user ID is released and reused.
* No packet has arrived since monitor attachment.
* Wall time moves backward while monotonic time advances.
* A packet arrives at the idle timeout boundary.
* A packet arrives during pause, snapshot create, Firecracker termination, and
  status record publication.
* Snapshot create fails after pause.
* Firecracker termination fails after a complete snapshot.
* Manifest publication fails.
* metald exits after snapshot publication but before status publication.
* metald restarts while a VM is sleeping.
* Snapshot load fails and terminates the new Firecracker process.
* Wake succeeds and status publication fails.
* A wake event is duplicated, delayed, or belongs to a released user ID.
* The ring buffer is full for the first sleeping packet.
* Desired stop, pause, destroy, restart, compute change, and is_sleepy disable
  arrive while the VM is sleeping.
* Daemon shutdown starts while a wake restore holds the VM operation lock.

Review and rollout gates
------------------------

Gate 1 follows chunk 1B. A reviewer must approve the tap0 TCX placement and the
no-reader host proof. Do not start Phase 2 without this evidence.

Gate 2 follows chunk 2E. A reviewer must approve snapshot file ownership,
compatibility validation, file lifetime, and two-cycle warm stop and start. Do not
add automatic policy before the direct runtime path is reliable.

Gate 3 follows chunk 2H. Deploy with [sleep].enabled false. Exercise the activity
observer on one host and inspect background traffic. If regular host-generated
frames prevent idleness, identify the exact Ethernet type and source before a
separate reviewed filtering change.

Gate 4 follows chunk 3E. Enable one internal sleepy VM with a long timeout. Check
wake latency, snapshot disk use, page-cache pressure, and failed wake logs.

Gate 5 follows chunk 3F. Expand by host cohort. Keep a fast configuration rollback
that disables new sleep decisions. Disabling the feature must restore currently
sleeping VMs before the eBPF monitor stops.

Out of scope for these phases
-----------------------------

* Moving a sleeping VM or its memory snapshot to another host.
* Uploading sleep snapshots through the image snapshot API.
* Reliable buffering or replay of the packet that triggers wake.
* Preserving established TCP or vsock connections across sleep.
* Diff memory snapshots, userfaultfd, prefetch, or snapshot compression.
* Sleeping from CPU, disk, console, or application-level idleness.
* Per-tenant or per-VM idle timeout values. The only timeout is the Metal-wide
  [sleep].idle_timeout value.
* Parsing application protocols in eBPF.
* Changing the controller outside this Metal module. That work needs a separate
  plan after the Metal request and response contract is merged.
